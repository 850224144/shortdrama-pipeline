## 3. 状态与门禁

`INGESTED → ANALYZED → PROPOSED → PLAN_APPROVED → PRODUCING → ASSETS_REVIEWED → ASSEMBLED → FINAL_REVIEW → DELIVERABLE`
异常：`NEEDS_INPUT / INSUFFICIENT_MATERIAL / FAILED / CANCELLED`。

- 首集必须显式确认；字幕必须与源片同批确认，哈希变化即要求重新确认。
- 方案：最多 3 个实质差异方案；策划编辑产生新 `plan_revision_id`；旧审批只作历史。
- 制作：只有最新且有效的审批版本能创建任务；同一项目同时只允许一个运行作业。
- 片段：仅允许从 `import_root` 或项目 `imports/` 导入；旧方案片段标记 `history`，不能验收进时间线。
- 时间线：只取已验收片段的有效区间；同一片段重复使用需显式理由（第一版默认阻断）。
- 质检：`PASS / PENDING / FAIL`；关键 PENDING 阻断交付；技术参数变更只重跑技术项。
- 交付：必须四层通过 + 最终完整观看人工验收；导出不发布，并写 `manifest.json`。

## 4. 已采用的默认值

设计 §3.4 五项尚未由业务拍板，按文档建议值实现并可在项目策略中覆盖：

- 交付时长 30–40s，目标 35s；`allow_shorter_than_min=false`。
- `audio_mode=original_audio`，`audio_permission=unconfirmed`（未确认时交付阻断）。
- 生成 `production_mode=manual_generation`，分析 `analysis_mode=assisted`，`external_media_transfer=disabled`。
- 不提供自动付费或外传；创意验收阈值沿用评分权重（opening20/clarity20/escalation20/turn15/ending15/feasibility10）。
- Web 界面仅提供 `/api/hooks` 接口，未新增前端页面。
