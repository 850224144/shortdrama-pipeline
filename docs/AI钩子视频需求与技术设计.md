# AI 钩子视频需求与技术设计

> 文档版本：v1.0
> 创建日期：2026-11-17
> 状态：设计基线草案，待开发前确认；不是已实现功能清单。
> 适用项目：短剧工坊 / ai_hook_tool。
> 本次范围：保存需求和技术方案，不执行开发、安装、素材外传、付费生成或发布。

## 1. 决策摘要

将当前“关键词选句 → 生成片段 → 拼接”升级为“首集证据分析 → 剧情事件理解 → 多方案钩子策划 → 预演审批 → AI 重制 → 分层验收”。

最终交付是一条忠于首集、人物关系清楚、情绪或冲突有递进、具有继续观看理由的 AI 钩子视频，而不是一组提示词或一个达到时长要求的 MP4。

跨剧泛化依赖事件、人物关系、因果与时序建模，不依赖针对单剧增加关键词。系统允许输出“素材不足”或“需要人工核对”，禁止为了成功率伪造剧情、重复对白或拖长镜头凑时长。

三个独立目标：

1. 理解正确：明确发生了什么、谁对谁做了什么，以及证据在哪里。
2. 策划有效：形成可理解、有吸引力、有递进的短叙事。
3. 制作忠实：生成和剪辑准确执行批准方案，不因人物、对白或节奏错误破坏策划。

## 2. 依据、现状与证据边界

### 2.1 用户需求

- 当前钩子视频缺乏看点，不能仅修技术合规或提高画质。
- 方案不能只适用于一部剧，后续新剧也应能正确制作。
- 需要可开发、可测试、可验收的详细需求与技术方案。

### 2.2 本次代码与产物核查

以下是截至文档创建时的本地核查，不代表已观看并评价全部成片：

| 现状 | 位置 | 设计处理 |
|---|---|---|

### 2.3 外部研究边界

本轮联网工具不可用，未完成 GitHub 最新版本、许可证与成片能力核验。不得将未核实的外部特性设为必须依赖。

## 3. 范围、默认值与待确认项

### 3.1 沿用的工作边界

- 默认只分析第一集；其他集只允许读取必要文件名以识别集号，不自动解码、转写或抽帧。
- 最终方向为 AI 重制钩子；原片粗剪仅作内部策划验证与对照，不自动发布。
- 沿用现有工坊，不重写下载、上传和整个 Web 应用。
- 第一版保留人工在生成平台操作，系统管理制作任务、导入、剪辑与验收。
- 无足够证据不编造；未经授权不发送素材、不付费生成、不发布。

### 3.2 建议默认值，开发前可调整

| 配置 | 建议默认 | 说明 |
|---|---|---|
| target_duration_sec | 35 | 策划目标，不是每条必须精确35秒 |
| delivery_duration_range_sec | [30, 40] | 项目策略；素材不足不强凑 |
| proposal_limit | 3 | 最多3个，允许只有1个或0个 |
| aspect_ratio | 9:16 | 分辨率、帧率复用现有配置 |
| production_mode | manual_generation | 不依赖生成 API |
| analysis_mode | assisted | 模型辅助，人工核对关键事实 |
| external_media_transfer | disabled | 按具体 provider 和数据类型显式允许 |
| publication | disabled | 此功能只交付，不自动上传或发布 |

调用额度、金额预算、生成重试上限不在文档中虚构固定数值。未配置付费额度或外传权限时，不启动相关外部任务。

### 3.3 非目标

- 不承诺每部剧首集都精彩，不承诺爆款或留存率。
- 不自动扫描后续集补反转。
- 不默认新增解说文案，不把全 AI 路线改为原片搬运。
- 不默认克隆真人声音，不默认拥有原片音频、演员形象的使用授权。
- 不在第一版引入 Celery/Redis、前端框架迁移、多机调度。
- 不把法律或平台合规判断包装成技术检测结果。

### 3.4 开发前需确认

1. 30–40秒是否作为第一版正式交付范围，还是只设最短时长。
2. 原声音频使用权限及默认音频模式。
3. 可用的文本/视觉服务、允许发送的数据类型、费用上限。
4. 验证集素材授权、人工评审安排与冻结的创意验收阈值。
5. 首期是否同时交付 Web 界面；建议 CLI 与服务层先完成，Web 为第一版完整交付组成部分。

## 4. 用户流程与输入输出

### 4.1 标准流程

1. 创建项目，选择素材目录。
2. 确认首集、字幕归属、角色参考和素材版本。
3. 分析首集对白、镜头、人物与事件。
4. 处理关键识别疑问。
5. 生成最多3个有实质差异的钩子方案。
6. 观看原片粗剪或分镜预演，修改并批准一个方案。
7. 生成逐镜制作任务，准备角色/场景参考。
8. 人工生成并按任务导入；核验片段和可用区间。
9. 按正式时间线剪辑，制作字幕与混音。
10. 技术检测、内容核对、完整观看后批准交付。

### 4.2 输入

必需：首集视频、明确的首集选择、输出策略。

可选：首集字幕/转写、剧本、简介、角色图、题材偏好、制作风格。

不得把简介或未对齐剧本中的后续情节当作首集已发生事实。

### 4.3 输出

- 素材与范围确认记录。
- 可定位原片的证据列表。
- 人物关系与剧情事件。
- 候选钩子方案、选择/舍弃理由、待核对项。
- 方案预演及审核记录。
- 逐镜生成任务与参考包。
- 导入片段、有效区间和逐镜验收。
- 时间线、成片、QC 与交付清单。

## 6. 素材隔离与证据层

### 6.1 目录布局

```text
ai_hook_tool/workdir/projects/<project_id>/
  project.json
  project.sqlite
  assets/
    asset_manifest.json
  runs/<run_id>/
    evidence/
    story/
    proposals/
    previews/
    reviews/
    generation/
    timeline/
    output/
    qc/
```

源片默认只保存受控引用，不复制整集。缓存使用内容寻址，可以物理共享不可变数据，但项目引用与权限隔离；不能靠同名文件判断同一素材。

### 6.2 素材身份与缓存

SourceAsset 记录：asset_id、项目ID、角色类型、绝对路径、SHA-256、文件大小、媒体时长、流信息、集号、识别依据及确认状态。

- 文件大小和修改时间用于快速筛查变化。
- 复用的正确性依据是内容哈希与分析配置，不是路径名称。
- 缓存键包含素材哈希、分析器版本、模型标识、提示词版本、配置哈希。
- 分析或导出前检查源片是否变更；变更后不得沿用旧结果。
- 视频检查、生成导入前后发生变化时，标记输入不稳定，停止使用该产物。

### 6.3 首集选择

- 明确匹配 E01、EP01、第1集及现有合法命名规则。
- 多个可能首集、同集多个版本时让用户选择，不仅按目录深度猜测。
- 无明确集号时进入 NEEDS_INPUT，允许用户显式确认某文件为首集并记录依据。
- 只有后续集时不自动降格选最小集号。

### 6.4 字幕和转写

优先匹配已确认首集的字幕；依据文件归属、集号、时间覆盖等校验，歧义时要求确认。SRT/VTT/TXT 应使用各自解析器归一化，不能统一按原始文本行解释。

转写保留 utterance_id、start_ms、end_ms、文本、可选词级时间码、说话人标签、来源、置信信息和人工修订历史。识别模型未提供置信值时为 null，不伪造概率。

关键否定词、人物名、身份揭示、决定性动作存在疑问时必须核对。修正保留原文与修订者，不覆盖证据历史。

### 6.5 证据等级

- 原片音频/画面：事实核对主要来源。
- ASR、字幕、视觉观察：可定位的分析结果，允许出错。
- 剧本：辅助说明，必须与首集对应。
- 简介：背景，禁止直接转为首集事实。

每条解释记录 evidence_ids、source_type、verification_status；自动提取完成不等于已人工核实。

## 7. 剧情理解与视觉分析

### 7.1 事件模型

事件描述一个有参与者、目标、行为、阻碍或信息变化的完整片段，不是单句关键词。

```json
{
  "event_id": "evt_012",
  "source_asset_id": "asset_e01",
  "source_spans": [{"start_ms": 40000, "end_ms": 47000}],
  "participants": ["char_01", "char_03"],
  "action": "主角提出请求，对方拒绝",
  "goal": "改变当前处境",
  "obstacle": "对方掌握决定权",
  "stakes": ["失去机会"],
  "new_information": ["对方拒绝提供帮助"],
  "prerequisite_event_ids": [],
  "evidence_ids": ["utt_035", "obs_018"],
  "verification_status": "needs_review"
}
```

以上为结构示意，不是真实素材记录。

事件关系包括：前提、原因、结果、揭示、回应、对比。模型可以提出关系，但关键关系不能无证据强行确认。

### 7.2 人物模型

- char_id、姓名或暂定名称、别名。
- 说话人标签与画面轨迹分别记录。
- 已确认关系及其证据。
- 外观、服装、参考图版本。
- 口播/旁白属性。
- 未确认字段。

声音聚类不直接确定姓名；画面可见人物不直接确定说话人；角色缺失不以默认主角替代。

### 7.3 双时间线

分别保存源片呈现顺序和剧情实际时序。实际时序允许 unknown 或局部顺序约束，不强迫模型补完整时间轴。

倒叙开场可以使用，但要有明确的呈现意图，不得造成“反击变成原因”“幻想变成现实”等事实误导。

### 7.4 视觉处理

1. 使用镜头边界检测定位采样点。
2. 每个镜头抽代表帧，对动态变化增加采样。
3. 对候选片段检查人物、动作、道具、表情、反应与场景转换。
4. 动态动作以连续帧、短片段或人工观看确认，单帧不足时标记未确认。
5. 人工修正优先于未经核实的模型推断，重新分析时不得静默覆盖。

首期可采用联系表加人工查看，不要求先采购视频模型。外部视觉服务必须受素材外传权限控制。

## 8. 通用钩子策划

### 8.1 戏剧机制库

支持危机升级、关系背叛、人物反差、权力逆转、身份疑问、目标受阻、误解与揭示、情感选择、喜剧反转。

题材仅影响候选偏好和表达风格，不强制存在某种人物关系或事件。甜宠不必争吵，悬疑不必在钩子内揭底，喜剧不能把笑点误删为无效铺垫。

### 8.2 候选召回

信号来源：事件转折、人物关系变化、新信息、视觉动作、反应、声音情绪、辅助关键词。

候选必须扩展至完整语义和动作边界；补齐理解所需的上下文。不得只截取“这一巴掌”等缺关键宾语或原因的碎片。

分析覆盖整个首集。首集过长时分块并保留重叠上下文、覆盖清单及全局合并；不能只截取最前20条候选便宣称分析完成。

### 8.3 方案结构

每个方案包含：卖点、戏剧机制、主视角、人物关系、开场、必要处境、升级、转折或情感变化、结尾观看动机、源片引用、计划时长、制作复杂度、风险与舍弃理由。

五个必答问题：

1. 观众最先看到什么，为什么值得停留？
2. 谁想得到什么？
3. 谁或什么在阻碍？
4. 中间新增了什么信息，局面如何变化？
5. 结尾使观众想知道哪件具体的后续事情？

不是每类题材都要求强冲突，但必须有可表达的情绪/认知变化和观看动机。

### 8.4 新旧规则替换

取消原片首3秒开场限制、原片前30秒升级限制、固定15+15秒分段、固定镜头数、整段生成片段必须用满等规则。

改为成片节奏约束：开头尽快建立看点；内容可来自首集任意合理位置；镜头长短服从对白、动作与反应；结尾必须建立在前文理解之上。

不得用“结尾带问号”“角色标签为 cliffhanger”代替实际悬念。

### 8.5 方案差异

对主视角、戏剧机制、开场事件、核心转折、结尾问题和事件顺序进行比较，并报告源片区间重合度。

不设置“一切片段不得重复”的死规则：同一强转折可以被不同角度使用，但结构必须有实质差异。重复方案合并，只输出有效数量。

### 8.6 策划评价

初始排序权重：开场20、清晰度20、递进20、转折/新信息15、结尾动机15、制作可行性10。权重为待验证的工程初值，不是爆款公式。

每项评价必须有理由及对应片段。事实、人物、因果硬错误直接阻断，不能被高总分抵消。

校验分两层：确定性引用/时长校验；语义批评与人工复核。语义批评可由独立提示步骤承担，但不把模型自评当作独立事实证据，也不要求多智能体系统。

## 9. 预演、编辑与审批

### 9.1 预演产物

- 优先：有权使用的首集原片粗剪，检验故事与节奏。
- 备选：关键帧、对白、临时音频与时长构成的分镜预演。
- 必须标记“内部预演/未正式交付”，不得混同最终AI成片。
- 记录是否缺少动态画面、音频或人工视觉核对。

### 9.2 编辑能力

替换开场、删除弱段、补充前提、调整结尾、修正人物/对白/时间码、选择机制并重新策划。每次产生新版本。

退回原因使用可扩展代码：OPENING_WEAK、RELATION_UNCLEAR、NO_ESCALATION、SPOILER_TOO_EARLY、PACING_SLOW、INSUFFICIENT_REACTION、FACT_ERROR、OTHER，并允许备注。

### 9.3 审批绑定

审批记录 plan_revision_id、plan_hash、evidence_revision、source_hashes、reviewer、timestamp、decision、notes、approved_scope。

编辑对白、人物、动作、顺序、关键切点或结尾后，相应策划审批失效；后续制作和最终审批沿依赖图失效。技术参数调整只重跑受影响的技术检测，不必重批未变更的故事。

未批准可以分析和导出预演，不可创建正式生成任务。旧审批不可跨版本复用。

## 10. AI 制作与时间线

### 10.1 任务与镜头分离

一个叙事镜头可对应多个生成尝试；一个长生成片段可以只使用部分有效区间。首次实现限制同一片段的重复叙事使用，必要时要求显式理由与审核，避免重复凑时长。

GenerationTask 必须包含：project_id、plan_revision_id、shot_id、参考版本、已批准动作、对白/音频模式、镜头表达、连续性要求、禁止新增内容、请求时长、预期有效时长、证据引用。

机位、构图等表达可设计；人物身份、关键动作和事件结果必须源于证据。表达创新与事实新增分字段保存。

### 10.2 参考包

按项目保存角色、服装、场景、道具和视线/站位约束。参考包有版本及审批，人物无法区分或关键动作主体不清时先核对。

### 10.3 音频模式

1. 原声驱动重制：先确认音频使用权限，区分口播和旁白。
2. 重新配音：使用授权或通用声音，台词与批准文本一致；不默认声音克隆。
3. 生成器同步音频：对实际音轨重新识别和人工抽核，不能依靠提示词认定正确。

默认不新增解说。若未来启用解说型产品，需独立模式、原创解说标记和单独审批。

### 10.4 人工生成适配器

导出任务包，用户在平台生成后选择任务导入。导入记录文件哈希、provider或人工来源、attempt、媒体信息、可用区间、人物/动作/对白验收状态。

不扫描“最新MP4”自动收片。旧版本任务导入可保存为历史，但不能直接选入当前时间线。

### 10.5 时间线结构

```json
{
  "timeline_revision_id": "tl_004",
  "plan_revision_id": "plan_003",
  "timebase": "milliseconds",
  "video_items": [
    {
      "shot_id": "shot_02",
      "generated_asset_id": "gen_018",
      "source_in_ms": 1200,
      "source_out_ms": 4600,
      "timeline_start_ms": 3500,
      "timeline_end_ms": 6900,
      "speed": 1.0
    }
  ],
  "audio_tracks": [],
  "subtitle_events": [],
  "overlays": []
}
```

示例不代表真实制作记录。校验入出点合法、媒体范围、时间换算、轨道重叠/间隙、音画同步及片段版本。

字幕按最终音轨对齐。长句换行或分字幕事件，不直接截断。禁止靠静音音轨掩盖缺失对白，缺音频必须明确失败或待处理。

不足时长应回策划补必要内容；无内容可补则标记不可满足当前规格。不默认循环、慢放或空镜拖长。

## 11. 质量门禁与交付权限

### 11.1 四层检查

| 层 | 主要内容 | 核验手段 |
|---|---|---|
| 来源 | 首集、素材哈希、证据引用 | 确定性校验与人工疑问处理 |
| 叙事 | 人物、处境、递进、因果、结尾动机 | 自动辅助及方案审批 |
| 生成 | 错脸、错角色、错动作、错对白、可用镜头 | 检测与逐镜验收 |
| 交付 | 音视频流、时长、黑帧、响度、字幕、标识 | 技术检测及完整观看 |

### 11.2 检查结果

检查项包含 check_id、severity、status、evidence_refs、reason、detector_version、review_required。status 为 PASS、FAIL、PENDING、WARN。

独立计算 preview_allowed、production_allowed、delivery_allowed。关键项 PENDING 不允许交付，非关键警告是否接受必须由交付策略确定并记录。

技术指标不能证明创意质量，模型评分不能代替人工签核。

### 11.3 必须阻断交付

- 跨剧、跨集、旧素材污染。
- 影响剧情的无证据事实或相反语义。
- 关键角色身份、动作主体错误。
- 关键台词遗漏、反义、说话人错误。
- 未批准或已失效方案。
- 必要视觉/音频核对未完成。
- 无法验证或不满足规定的媒体质量。
- 本项目交付策略要求的AI标识缺失。
- 最终人工验收未批准。

与当前“错脸/标识缺失仅软告警”的行为不同，此变更需明确迁移和回归测试。

## 12. 数据模型与持久化

### 12.1 主要实体

Project、Run、SourceAsset、EvidenceRevision、Evidence、Character、StoryEvent、HookProposal、PlanRevision、Review、GenerationTask、GeneratedAsset、TimelineRevision、QCReport、Delivery、JobEvent。

核心关系：

- Project 具有多个 Run 和 SourceAsset 引用。
- Run 锁定证据版本，生成多个 HookProposal。
- HookProposal 具有不可覆盖的 PlanRevision。
- Review 绑定具体版本和内容哈希。
- GenerationTask 绑定批准的 PlanRevision 与 shot_id。
- GeneratedAsset 绑定任务与尝试次数。
- TimelineRevision 引用已验收生成片段。
- Delivery 绑定时间线、QC、最终审批和文件哈希。

### 12.2 存储分工

项目级 SQLite 是任务状态、修订索引、审批和依赖关系的权威来源；不可变JSON是可审阅的内容快照，不存在两份可随意编辑的真相。

落盘采用临时文件写入、校验和计算、同盘原子替换，再事务登记引用。失败产生的无引用文件在恢复时标为孤立产物，不自动当成功结果。

启用 schema_version、数据库迁移、外键、唯一约束和受控事务。所有时间使用 UTC 存储，界面转换本地时间；媒体时间使用整数毫秒。

### 12.3 并发

- 版本更新采用乐观并发控制，传 expected_revision，不匹配返回409。
- 每个项目的变更任务受互斥控制；GPU/生成资源通过适配层接入现有资源限制。
- 长任务不持有SQLite写事务。
- 双击启动使用 idempotency_key 去重。
- 不在应用 import 时自动启动新钩子分析或生成。

## 13. 状态流转、恢复与失效传播

主业务阶段：

```text
CREATED → INGESTED → ANALYZED → PROPOSED → PLAN_APPROVED
→ PRODUCING → ASSETS_REVIEWED → ASSEMBLED → FINAL_REVIEW → DELIVERABLE
```

等待/异常状态：NEEDS_INPUT、INSUFFICIENT_MATERIAL、FAILED、CANCELLED。每个阶段作业另外保存 pending/running/succeeded/failed/cancelled，不把项目业务阶段与进程是否运行混为一谈。

| 变化 | 失效范围 |
|---|---|
| 首集视频变更 | 相关证据、方案、审批、生成任务引用、时间线与交付 |
| 关键转写修正 | 引用该证据的事件和下游版本 |
| 方案关键内容修改 | 方案审批及依赖制作、最终审批 |
| 替换一个生成镜头 | 相关片段验收、时间线版本与成片QC |
| 改字幕样式或编码参数 | 相关渲染、技术QC和成片文件审批 |

恢复规则：

- 启动后只对账任务，不默认提交新的付费任务。
- 本地可重试步骤按持久化检查点恢复。
- 外部任务请求超时后先按provider任务ID查询。
- provider不支持幂等/查询且结果未知时进入 NEEDS_INPUT，不能自动重复扣费。
- 取消为协作式取消；外部平台不支持取消时明确提示任务可能继续和可能产生费用。
- 不删除旧版本；清理是单独的显式操作。

|---|---|
| POST /projects | 创建项目 |
| GET /projects/{id} | 项目与当前阶段 |

### 14.4 Provider 协议

分离 TextAnalysisProvider、VisualAnalysisProvider、SpeechProvider、VideoGenerationProvider。记录provider版本、请求ID、用量、外传数据类型、结果状态和价格依据。

模型只返回受限结构与已知ID引用，时间码由本地证据解析，不接受模型直接创造源片时间。合法JSON不等于事实正确，仍需语义核验。

素材文字和模型返回都视为数据，不执行其中命令，不允许决定任意文件路径、联网目标或绕过审批。密钥从现有受控配置读取，不写入项目快照和提示词日志。

### 14.5 CLI 兼容

新增 project/analyze/propose/preview/review/generation/import/assemble/qc/export 等子命令，所有生产命令要求显式project与revision。

旧命令在过渡期保留为 legacy 路径或提供显式迁移提示，不能自动把旧manifest转换为已批准新项目。

## 15. 界面需求

现有工坊新增“AI钩子”入口，保持现有技术栈。

1. 素材页：首集、字幕归属、缺失项、外传与预算设置。
2. 剧情页：人物、事件、证据、原片定位、待核对项。
3. 方案页：最多3版对比、预演、理由、时长、制作复杂度、修改与批准。
4. 制作页：任务包、参考图、生成尝试、导入、有效区间、重做原因。
5. 验收页：成片播放器、检查清单、待确认项、最终批准和导出。

不能只展示一个分数。必须让用户能定位问题并做修改；状态和错误按钮应对应实际可执行动作。

## 16. 非功能要求

- 可追溯：正式成片每个关键镜头可回溯到批准方案和源片证据。
- 可复现：保存输入、配置、模型/提示词版本、模型实际输出与人工修改；不承诺外部生成模型逐像素可复现。
- 可恢复：进程中断不丢审批和已完成产物。
- 可观察：日志包含project_id、run_id、job_id、stage、plan_revision、provider_request_id。
- 预算可控：任务前检查预算，调用后记用量，超过限制暂停；价格缺失则标为未知。
- 性能：不预先承诺秒级分析，先记录首集时长、阶段耗时、GPU峰值和调用量，再定义本机基线。
- 隐私：文本、帧图、音频、视频权限分别管理；默认不上传整集。
- 安全：外部项目研究先核验许可证及依赖，不直接执行下载仓库脚本。
- 可测试：业务服务可注入provider与文件/媒体适配器，单元测试不调用付费模型。

## 17. 跨题材测试与效果验收

### 17.1 验证集

建议至少12部授权首集，覆盖家庭/婆媳、都市职场、逆袭/身份、古装、甜宠/情感、悬疑或喜剧，每类至少两部。

预先固定开发集与保留集，记录剧ID、素材哈希、题材、时长、叙事特点和人工标注。保留集不能被逐剧关键词调参污染；调参使用过的样本不再算盲测。

### 17.2 困难样本

- 首集无明显冲突；前3秒弱、后半集强。
- 少对白、动作主导；多人同声；旁白与口播交替。
- 闪回、倒叙、重生；关系复杂；人名错识别。
- 字幕错集、多版本首集、目录混剧。
- 连续换剧、缓存被修改、源片中途替换。
- 无参考图、模型不可用、生成片段错身份。
- 不足30秒有效内容、只能形成一个方案。
- 审批后编辑、重复点击、崩溃恢复、外部任务结果未知。

### 17.3 自动化测试分层

| 层 | 内容 |
|---|---|
| 单元 | 集号/字幕匹配、缓存键、时间码、schema、引用校验、门禁、审批失效 |
| 契约 | provider合法/非法输出、未知ID、越界时间、错误类型、API版本冲突 |
| 集成 | 临时项目完整状态流、持久化、重复请求、恢复和迁移 |
| 媒体 | 合成素材FFmpeg渲染、入出点、字幕、音画同步、损坏文件 |
| 创意 | 跨题材预演与最终成片的人类盲评 |

CI自动跑单元和不触网契约测试。媒体集成在具备FFmpeg的独立任务运行。付费模型与真实素材评估必须显式触发，不能混入普通CI。

### 17.4 对照实验

同一首集、相同目标时长、相近制作预算下比较旧流程、新流程、人工参考版本。分别比较预演与最终AI成片，定位策划与生成各自的损失。

匿名随机顺序观看，记录：开场吸引力、人物/处境清晰度、递进、结尾动机、拖沓、事实错误、人物一致性与总体偏好。保留评审分歧，不只取平均分掩盖问题。

### 17.5 验收标准

确定性要求：

- 在定义测试集内跨剧/跨集污染为零。
- 正式分镜关键事实全部有有效证据引用。
- 所有关键修改触发相关审批失效。
- 关键PENDING不能交付。
- 素材不足正确阻断，不伪造成功。
- 重试和恢复不静默重复外部生成。

创意要求：开发前冻结评审协议和通过阈值。建议至少达到“新流程在保留集多数样本上被优先选择，且没有明显退步的题材”。这只是第一版验收目标，不构成统计上的普遍效果保证。

模型评分不等于真实留存；上线观看数据仅在授权、可比条件下另行评估，不虚构提升比例。

## 18. 实施计划与退出条件

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| P0 隔离与证据 | 项目库、首集确认、缓存绑定、字幕解析、schema | 换剧/错集/缓存失效与基础恢复测试通过 |
| P1 通用策划 | 事件/人物模型、多方案、校验、预演 | 开发集跨题材改善，不靠单剧特判 |
| P2 审核闭环 | 编辑、审批、版本失效、Web方案比较 | 未批准不能生产，旧批准不能复用 |
| P3 AI制作 | 任务包、参考包、导入、逐镜验收、时间线 | 最终视频准确实现批准方案 |
| P4 验收与批处理 | 分层QC、保留集评价、恢复、预算、批量项目 | 通过冻结的验收协议且失败路径可控 |
| 后续可选 | 授权生成API、更强视觉自动化 | 证明质量或成本收益后再接入 |

P0至P4是完整第一版。不得因P1能生成JSON就宣布功能完成，也不得用一部剧效果好代替跨题材验收。

推荐每阶段独立分支或提交单元；当前工作区已有其他未提交改动，实施前先确认其归属，不混入本功能。

## 19. 迁移与回滚

- 新流程使用独立project目录和新schema，旧workdir保持只读兼容。
- 旧manifest可显式导入为legacy参考，但审批状态一律pending。
- 旧共享转写无法证明归属时不自动复用。
- 初期通过显式新入口启用，不替换现有切片和上传默认路径。
- 回滚关闭新入口即可；不回写或删除旧素材、旧成片、上传数据库。
- 更新README、旧设计文档、CLI帮助和测试，让“首集范围”与“原片前三秒限制”的区别保持一致。

## 20. 风险与处理

| 风险 | 处理 |
|---|---|
| 模型编造人物/动作 | 已知ID引用、证据链、关键事实人工核对 |
| 模型输出格式正确但剧情错误 | 确定性校验与语义/人工核验分开 |
| 首集没有足够看点 | 返回不足原因，可人工调整规格，不自动分析后续集 |
| 过度追求冲击导致误导剪辑 | 双时间线、前提检查、方案预演审批 |
| 全AI动作与人物不稳定 | 先批准参考，按镜头重做，严格验收 |
| 原片预演好看但AI成片差 | 两阶段对照，定位表演、动作、声音和节奏损失 |
| 预算超支 | 任务前预算检查、持久化用量、未知结果不盲重试 |
| 人工审核成本高 | 先自动定位疑问、只审核关键节点，但最终完整观看不能省略 |
| 对开发样例过拟合 | 冻结保留集，不将剧名/台词写入生产规则 |
| 外部工具能力或许可变化 | 可替换适配器，接入前重新核实 |

## 21. 交付完成定义

功能只有同时满足以下条件才算完成：

1. 新剧可从独立项目进入整个流程，不需要改代码或临时加关键词。
2. 首集证据、人物、事件和方案能追溯，错误可修改。
3. 多方案真正有差异，或诚实输出有效数量不足。
4. 用户能观看、编辑、批准方案，审批与版本严格绑定。
5. 生成任务与片段可追踪，镜头可以局部重做。
6. 按时间线精剪，不依赖固定15+15秒和完整10秒拼接。
7. 关键事实、人物、对白及技术问题阻断交付。
8. 支持重启恢复、预算与外传控制。
9. 通过跨题材保留集及异常路径验收。
10. 文档、CLI、Web界面和测试口径一致。
