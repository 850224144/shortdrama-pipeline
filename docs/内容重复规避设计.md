# 内容重复规避设计（成品级感知哈希指纹 + 三重防重）

> 分支：`codex/pipeline-reliability` ｜ 状态：设计 ✅（2026-10-31）
> 背景：账号被平台提示"内容重复"——一部短剧生成的成品重复度很高。
> 用户结论：既往不咎，但必须规避再次发生（下次可能封号）。不确定是
> **生成侧重复**（多版本成片内容高度相似）还是**上传侧重复**（同一作品
> 被重复上传），本设计同时覆盖两者，并把检测结果落日志/报告以便溯源。

---

## 1. 问题定义

当前管线的防重现状（都是"名字/版本级"，**没有内容级**）：

| 环节 | 现有防重 | 缺口 |
|---|---|---|
| 多版本差异化 | `_analyze_drama_arc` 规划层（opening_ep 互异、angle/order_type 变化） | 差异化只在**规划层断言**，**无成片视觉层验证**——V1–V8 开头集/顺序不同，但素材池相同、相似度高，平台仍判重 |
| 交付选择 | `_select_best_videos` 只按**时长**（210–300s）取前 8 | **不查版本间内容重复**——8 个相似版本全部交付 |
| 上传幂等 | `upload_records` 的 `drama_name+version+account` 三元组 | **不查内容**——同一剧 V1–V8 是不同 version，全部上传；同内容跨剧/跨批次重复也放行 |
| 剧名级防重 | `processor.is_fuzzy_duplicate`（剧名模糊）、`output` 下已有成片跳过 | 仅同名剧；素材复用/内容撞车不覆盖 |

**根因判断**：重复度高的成片，几乎必然来自"同一批高光素材池"被多个版本反复使用
（生成侧）以及"所有版本都上传同一账号"（上传侧）。两者都缺内容级检测。

## 2. 方案总览：成品感知哈希指纹 + 三重防重

对每个交付成片计算**帧级感知哈希序列**（内容指纹），据此做三重检测：

```
成片.mp4 ──ffmpeg fps=1 采样──► 灰度帧序列 ──dHash──► 帧哈希序列(64bit/帧)
                                                              │
              ┌───────────────────────────────────────────────┤
              │ ① 生成侧：版本间相似度（交付前剔除高重复）        │
              │ ② 成片内部：内部重复片段检测（告警）             │
              │ ③ 上传侧：上传前指纹查重（拒收同内容）           │
              └───────────────────────────────────────────────┘
```

### 2.1 指纹算法

- **采样**：`ffmpeg -i <video> -vf "fps=1,scale=64:64" -f rawvideo -pix_fmt gray -`
  一次导出灰度帧流，numpy 切帧（每帧 64×64 字节）。210–300s → 210–300 帧。
- **帧哈希**：每帧算 64-bit 差分哈希（dHash，8×8 相邻像素比较 → 64 bit）。
  抗亮度变化、抗轻微噪声；对转码/缩放/水印/裁剪鲁棒（videohash 同源思路）。
- **指纹**：`list[int]`（每帧一个 64-bit int），序列长度 = 时长秒数。
- **存储**：`content_fingerprints` 表，`hash_seq` 存 BLOB（每帧 8 字节大端，
  300s ≈ 2.4KB/成片，可忽略）。同时存 `duration`、`size`、`drama_name`、
  `version`、`account`、`video_path`、`filename`、`source`（cut/upload）、
  `uploaded`、`uploaded_at`、`created_at`。

### 2.2 相似度（滑动窗口匹配）

两序列 A（短）、B（长），窗口 = len(A)，在 B 上滑动（步长 1s）；
每位置计算 **A 中哈希与 B 对应帧 Hamming 距离 ≤ 0.25 的帧占比** = 该位置匹配率；
`similarity = max(匹配率)`。numpy 向量化，O(n×m)，300×300 → 毫秒级。

> 语义：similarity 高 = B 中存在一个连续区间与 A 的视觉内容高度重合 =
> "使用了相同素材"。这正是平台判"内容重复"的度量。

### 2.3 三重防重策略

**① 生成侧（交付前剔除）——硬性拦截**
在 `_select_best_videos` 之后、`_post_process` 之前，对 best_videos 两两算相似度：
- `similarity > DEDUP_HARD`（0.75）→ 判高重复，**剔除**其中"差异化弱"者
  （保留开头集唯一 + 时长更居中 210–300 + 更靠前的版本），记 `removed_reason='content_duplicate'`。
- `DEDUP_SOFT < similarity ≤ DEDUP_HARD`（0.5–0.75）→ 保留但写 **WARN + report**（提示疑似重复，便于人工复核）。
- 保留至少 `MIN_DELIVER`（3）个版本：若剔除后 < 3，**停止剔除**，只告警不拦
  （避免 0 交付/版本数不足），并记录"疑似重复但版本数不足，未剔除"。
- 被剔除版本的文件**不删除**（保留在 out_dir，人工可查），仅从交付集移除，
  写 `report.json` 的 `content_dedup` 段。

**② 成片内部（内部重复检测）——默认告警**
单成片指纹序列，窗口（10s）滑动自相似：发现同一素材段出现 ≥2 次且间隔 >15s
→ 记录 `internal_duplicate` 告警进 report。默认**不拦截**（短剧剧情合法回环），
仅暴露给人工/日志。

**③ 上传侧（入队前查重）——硬性拦截**
`add_to_queue` / `add_batch` 时，对 `video_path` 算指纹，查 `content_fingerprints`
表中**同账号**且 `uploaded=1`（已上传过）**或** `status IN ('pending','uploading')`
（已入队未传）的记录：
- 相似度 > `UPLOAD_DUP_THRESHOLD`（0.6）→ **拒收**，`duplicates` 附
  `reason='content_duplicate'` + 冲突记录 `{drama, version}`，日志 WARN。
- 跨剧同样命中（查全局，不限 drama_name）——堵"同素材被多剧复用"与"同一作品重传"。
- 指纹计算失败（ffmpeg 异常）→ **放行 + WARN**（保守放行，不因检测故障阻塞上传；
  与 R6 门禁"异常兜底"一致）。

**上传完成登记**：任务 `uploaded` 成功 → 置指纹行 `uploaded=1, uploaded_at`。
若该 video_path 无指纹行（生成侧未登记，如历史成片）→ 上传成功后补登记。

### 2.4 阈值标定（首次上线后）

初始保守值：`DEDUP_HARD=0.75`、`DEDUP_SOFT=0.5`、`UPLOAD_DUP_THRESHOLD=0.6`。
用已切的 1 部剧（V1–V8 成片）实测两两相似度分布，验证：
- 同剧不同版本（预期：相似度高，因素材池相同）——确认阈值能区分"版本间"vs"真不同素材"；
- 不同剧成片（预期：相似度低）。
阈值进 `CONFIG`（`content_dedup` 段），可环境变量覆盖（`SHORTDRAMA_*` 约定）。

## 4. 关键决策与风险控制

- **宁可少传，不可封号**：上传侧阈值（0.6）偏严，生成侧硬阈值（0.75）剔除高重复；
  两者都默认拦截，用户可下调阈值放宽。
- **误杀风险**：生成侧若剔除过多导致版本数 < 预期 → 停止剔除只告警，保底
  `MIN_DELIVER=3`；上传侧误拒 → 用户可人工复核（日志给出冲突明细）。
- **性能**：指纹计算每成片 ffmpeg 采样 ~2–5s（210–300 帧）；版本间两两 8 版 = 28 对，
  numpy 向量化毫秒级；上传查重每任务 1 次计算 + 索引查询。总计每剧 <1 分钟，可接受。
- **检测故障不阻塞**：指纹计算/DB 异常 → 放行 + WARN（沿用 R6 门禁"异常兜底"原则）。
- **与既有防重的关系**：不改 `is_fuzzy_duplicate`（剧名级）与 `drama+version+account`
  （版本级）——内容级是**新增**第三层，三者互补。

## 5. 测试计划

- `test_content_fingerprint.py`：帧提取形状/数量；dHash 稳定性（同帧重算一致）；
  dHash 抗性（亮度/缩放/轻微噪声 → 距离小）；`similarity` 相同=1.0、无关≈0、
  旋转/镜像 < 0.2；`internal_duplicate` 检出重复段；`FingerprintStore` 建表/upsert/
  相似查询（含 uploaded 过滤）。
- `test_content_dedup.py`：生成侧——mock `similarity`，构造高/中/低相似版本集，
  断言剔除/告警/保底 3 版；上传侧——预置指纹行，断言拒收 `reason='content_duplicate'`、
  跨剧命中、同版本放行、指纹失败放行。
- 回归：全量 `webapp/tests` 保持全绿。
- 冒烟（可选，`RELIABILITY_SMOKE=1`）：真实素材切 2 版不同切割 → 相似度低；
  同切割 → 相似度高，验证阈值方向。
